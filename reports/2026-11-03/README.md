# 对象级视频异常检测的视觉 Token 压缩方法与结果

**在 L40S 上，`global90` 将视觉 Token 减少 89.62%，平均每段从 35.70 秒缩短到 11.66 秒。** 12 段中，找全异常主体的片数与不压缩持平，均为 5 段；至少找对一个异常主体的片数从 8 降到 6。把压缩提高到 91.11% 后，`PM92` 和 `Merge92` 分别只找全 2 段和 3 段。八卡服务器的独立对照中，加入局部残差的 `dual_residual90` 找全 3 段，另 1 段待定，同机不压缩为 5 段。

正文各表取同一批 **12 段可评估异常视频**，使用官方 Qwen3-VL-8B-Instruct BF16、完整 10 FPS 视频加末帧。所有视频帧先经过视觉编码器，筛选与合并发生在进入语言模型之前。带 I3 截图的组保留全部截图和规则文字，各自与同机、同输入的不压缩基线配对。

### 实验怎样把异常定位到具体对象

正文采用 **I3 语言指认**。例如，模型要回答“谁在禁止骑行的广场上骑车”，输出应把“骑车”连到画面里可以唯一辨认的人和车。这里有三个不同的环节。

1. **准备能看清细节的输入。** 历史数据预处理用 YOLO11s 产生候选框，用 ByteTrack 在片内关联候选轨迹。程序优先选人，再考虑包、动物和移动的车辆等候选，每段最多选 12 条轨迹，从每条轨迹的首、中、末观测取框，去重后映射回原始 MP4 帧，向外留出边缘再裁图。给 Qwen 的图页只有裁图、帧号、原生帧索引和媒体时间。检测轨迹编号、候选身份表和参考答案均不作为推理输入。同一人可能在几张小图中反复出现，未被裁到的对象仍可出现在完整视频里。本轮 12 段实际使用的 42 张图页已按文件指纹与原 I3 输入逐一核对。[检测与跟踪](attachments/trackid232_v1/extract_candidates.py) · [候选选择](attachments/trackid232_v1/native_detail_contract_v1.py) · [原帧裁图](attachments/trackid232_v1/unlabeled_full_prepare_v1.py) · [未编号图页渲染](attachments/trackid232_v1/unlabeled_detail_contract_v1.py)
2. **模型根据动作和关系指认主体。** Qwen 同时接收完整视频、同源局部图和场景规则。提示要求它在每个事件里写出发生了什么（`evidence`）、对应的原生帧（`start/end`），再对相关对象写出外貌、携带物、本人动作或与人、车、地标的关系（`objects[].appearance`），注明角色（`role`）和它自身是否异常（`abnormal`）。`object_id` 由模型给当前片段中的对象命名，提示要求在可连续跟踪时复用。仅凭同名 ID 无法判定它指的是谁。[本次送入模型的实际提示](attachments/purity_ablation12_l40s_v1/outputs/clip_43f409d01d48ae2cecd52247/select90/DECISION_PROMPT.json)
3. **按视频核实指认。** 评估者将模型写出的“谁做了什么”与全时段原画面、原图和冻结的规则逐项对照。描述是否能排除同片旁人、被推者是否误写成施力者、骑车动作是否属于被点名的人，都会影响主体分。模型能够坐实真实动作但说错是谁时，事件列可得分，主体列失分。报告统计这种语义指认的片数；坐标、框重叠率和逐帧轨迹精度没有在这组实验里计分。[对象指认评分协议 V3](attachments/description20_fps10_rental_bf16_v1/evaluation_only/BINDING_PROTOCOL_V3.md)

**粉衣骑手的真实输出。** `select90` 与 `global90` 都在原生帧 `F024` 报告广场禁骑，甚至都把对象命名为“骑车人”。前者把外貌写成“穿白色上衣、深色裤子，正在骑行自行车”，实际指向步行者；后者写的是“穿粉色上衣，骑自行车”，与画面中唯一的骑手吻合。因此前者判为事件对、主体错，后者两项都对。定位在这一步由**异常动作与对象描述的对应关系**给出。[select90 原文](attachments/purity_ablation12_l40s_v1/outputs/clip_43f409d01d48ae2cecd52247/select90/decision/RAW.txt) · [global90 原文](attachments/purity_ablation12_l40s_v1/outputs/clip_43f409d01d48ae2cecd52247/global90/decision/RAW.txt)

**不同实验如何使用这套定位。** 正文的压缩方法仅改变传给语言模型的视频特征。代表格点保留原来的时空位置，热力图显示格点是否入选或对合并结果的贡献；程序没有把某个格点簇解码成“骑手 1”的轨迹，`entity_binding_enabled` 在这组推理中为 `false`。纯视频对照删除局部图，仍要求按相同字段描述对象。附录的两阶段 B 是单独的指认方式：第一阶段模型自己从画面建立名册，第二阶段根据规则从这份名册中选择一个或多个 ID，最终仍要回到相应描述和画面核实身份。[压缩器与模型的接入实现](attachments/purity_ablation12_l40s_v1/prune_merge_adapter.py)

### 怎样区分两列主体指标

这两列都按**视频段数**计分。正文每列的分母是同一批 **12 段异常视频**，每段在每列最多计 1 次。附录九段小试中的主体指标只评 6 段异常，另 3 段正常视频单独统计误报。

- **至少找对一个异常主体（Any）**。只要模型说对了片中一个实际发生的异常，并且从描述中能唯一认出是谁实施了该行为，或哪个物体处于该异常状态，这段视频就计 1。即使遗漏了另一名违规者，或同时误报了旁人，这一列仍计 1。只报对异常类别、只说“有人”，或只认对一名正常路人，都不能得分。
- **找全异常主体且无错绑（All）**。片中每个已确认异常的所有主体都要指对，而且不能把正常路人或仅受影响的人也判为异常，这段视频才计 1。因此，All 得分的视频一定也在 Any 中得分。

**实际例子**　在广场禁骑视频中，粉衣者骑车，前景白衣者步行。`dual90` 正确指出粉衣者违规骑行，同时又把白衣步行者报成骑手。这一段的 **Any = 1、All = 0、错绑 = 1**。L40S 表里 `global90` 的 **6/12** 则表示，12 段视频中有 6 段至少指对了一个真实异常主体；同一视频中指对多人也只算一段。[该片逐项评分](attachments/dual_anchor12_server_bf16_v1/evaluation_only/PAIRED_VISUAL_REVIEW_20261103.v001.json)

“事件”和“类别”分别评估实际动作及异常类别集合。“错绑”统计发生正向错误绑定的视频段数。`3+1?` 表示 3 段确认、另 1 段待定。视觉 Token 包含视频和保留的截图，全部 LLM Token 包含输入和输出。秒/段含单例准备、视觉编码和生成，排除共享解码及模型加载；不同方法的输出长度有差异。

## 1　L40S 的高压缩方法

这里的 `90` 和 `92` 是**目标削减率**。预算按视频与 I3 截图的视觉 Token 总数计算。假设视频有 `V` 个 Token、截图有 `I` 个，90 系列先给视频分配 `floor(0.10 × (V + I)) − I` 个位置，92 系列把系数改为 0.08。截图全留。如果算出的名额太少，程序采用预设的空间和时间保底数量，所以结果表列的是实际减幅。

**变化分怎么算。** 编码器每两个输入帧产生一个时间组。对组内每个格点，计算 `d = 1 − cos(当前主特征, 同位置的参考特征)`。参考从首组初始化，之后只有该格点被选为代表才更新。`d ≥ 0.10` 的格点及其周围一圈（3×3）进入优先区。排序分为 `d + 2 × 是否在优先区`。因此，树影和人物动作都可能加分；优先区内仍需竞争有限名额。

### `select90` 实际怎样把一段视频压小

1. **分时间名额。** 首组画面均匀划成最多 8×8 个分区，每区只取中部一个格点。扣除首组名额后，把剩余名额均分给后续时间组，余数依次分给靠前的组。
2. **分空间名额。** 每个后续时间组切成不重叠的 **8×8 格点窗口**，边缘窗口可小于 8×8。每窗先分 1 个名额，再按窗口顺序轮流分配剩余名额，直到用完。这样，变化小的窗口也能保住局部场景。
3. **窗内选点。** 每个窗口按上述分数从高到低取足自己的名额；同分时优先取原顺序靠前的格点。只更新入选位置的参考特征。
4. **生成短序列。** 入选位置的主特征和三路中间视觉特征（DeepStack）都取该位置的原始向量，沿用其原时空位置。其余格点直接丢弃，对任何输出向量的贡献都是零。`select90` 与 `pm90` 的代表位置完全相同，两者的区别在这一步。

**粉衣骑手视频的实际记录。** 视频有 22 个时间组，每组 23×40＝920 个格点，另有 960 个截图 Token。总视觉预算从 21,200 降到 2,120，其中视频只能占 1,160 个。首组取 64 个，后续 4 组各取 53 个、17 组各取 52 个。以 **1.40 秒**为例，920 个格点分属 15 个窗口，前 7 窗各取 4 个、后 8 窗各取 3 个，共留下 52 个。`pm90` 在同一时刻也输出这 52 个位置，但有 **917 个**源格点贡献特征；`select90` 只有入选的 **52 个**贡献特征。`global90` 也取 52 个，其中只有 **28 个**与 `select90` 重合。[选点代码](attachments/purity_ablation12_l40s_v1/purity_core.py) · [分窗及打分代码](attachments/purity_ablation12_l40s_v1/high_compression_core.py) · [该片热力图](attachments/purity_ablation12_l40s_v1/evaluation_only/visual_review_v1/clip_43f409d01d48ae2cecd52247.png)

## 2　L40S 的中等压缩方法

`70` 表示目标削减 70% 的全部视觉 Token。首组、末组及每隔 8 个时间组的画面保留全部格点，其余组均分剩余名额，每个 **4×4 格点窗口**先取一个代表，额外名额依次轮流分配。变化分、缓存更新和 3×3 优先区的定义见第 1 节。下面的五个方法分别改变窗内排名或聚合方式。

| 方法 | 窗内怎样选代表 | 未入选格点怎样处理 |
|---|---|---|
| `select70` | 按变化分排序，3×3 优先区加 2 分，取本窗名额内的最高分格点。 | 全部剪掉，仅取代表的原始主特征和三路 DeepStack。 |
| `merge70` | 与 `select70` 采用相同的代表位置和数量。 | 每个非代表归给同时间、同窗内主特征最相似的代表，全部成员按 `d + 0.01` 归一化加权，分别汇总四路特征。 |
| `prune_merge70` | 与 `select70`、`merge70` 的代表逐片相同。 | 先删除优先区外的稳定非代表，再把优先区内的非代表按与 `merge70` 相同的归属和权重合并。 |
| `norm_merge70` | 取格点主特征原向量的 L2 范数，除以该时间组最大范数；优先区仍按时间变化计算并加 2 分，然后在窗内选高分点。 | 同窗全部成员按相似度归属、按变化分加权合并。范数只改变选点排名。 |
| `random_merge70` | 用固定种子、空间索引和时间组索引生成可复现的伪随机分数，再给变化优先区加 2 分，按窗取点。 | 与 `merge70` 一样合并全部同窗成员。因此这组测试的是优先区机制下的随机排名。 |

## 3　双锚点选点与局部残差合并

八卡服务器 GPU3 上，四种配置分别跑同样的 12 段视频。`full_native` 将所有格点和四路视觉特征原样送入语言模型。`global90` 使用第 1 节的缓存变化分、3×3 优先区、全画面分散选点，只保留中心原向量。新方法沿用相同预算，逐步更换打分信号和合并规则。

- **`dual90`（双锚点，只选不合）**。对同一格点计算两个余弦差，一个对比上一原始时间组，一个对比首个原始时间组，分别乘 0.7 和 0.3 后相加。得分达到 0.18 的位置及其上下左右四邻居加 2 分。首组均匀选场景中心，后续按每组配额在全画面分散选点，四路均取原向量，其余格点丢弃。
- **`dual_residual90`（同中心，补入少量邻居）**。逐片复制 `dual90` 的代表位置。后续每组检查优先区里的非代表：与某中心横纵距离均不超过两格、主特征余弦相似度至少 0.85 时，归给合格中心中最相似的一个。中心收到成员后，其主特征为 **75% 原中心＋25% 邻居加权均值**；邻居按双锚点变化分加 0.01 分摊这 25%。没有合格成员时取原中心；三路 DeepStack 始终只取中心原向量。12 段共 908 个非中心格点通过这一规则参与合并。[双锚点和残差实现](attachments/dual_anchor12_server_bf16_v1/dual_anchor_core.py)

## 5　初版时序剪枝与连通区域合并

- **`full_i3`**。初版同机基线使用完整视频、原生分辨率的 I3 局部截图和规则，每个原生视频格点都保留。
- **`ours_literal_i3`**。首个时间组按 2×2 空间块取算术均值。后续将每个格点与**上一原始时间组**同位置比较，余弦相似度超过 0.90 就剪掉。对剩余格点，如果两点处于同组八邻域、相似度高于 0.80，就连边形成连通区域。每个区域用至多 5 个近邻估算密度，按密度峰值分数选最多两个中心，再把每个成员分给最近的中心，对成员原特征取均值。主特征和三路 DeepStack 使用相同分组，位置取中心的原始时空坐标。该方法由阈值和连通区域大小决定最终 Token 数。[连通及密度选点代码](attachments/description20_fps10_rental_bf16_v1/compression_core.py)

## 附　早期九段小试的其他压缩方法

早期小试含 6 段异常和 3 段正常。以下配置按各自机器的固定对照评分。这里的 `C50`、`C25`、`C125` 分别指内部视频时间组**保留** 50%、25%、12.5% 格点，与正文 `select90` 的目标削减率采用不同命名约定。

**C 系列的公共步骤。** 视频首尾时间组全部保留。每个内部组先预留展平空间索引中每隔 16 个格点的代表，再把相对上一原始时间组变化较大的位置加入候选池，候选不足时按变化量补足。在候选池中用主特征余弦差加空间距离计算密度峰值分数，补满本时间组的名额。对剩余候选，若同时间组、距中心横纵各不超过两格且主特征余弦相似度至少 0.7，就并入最相似中心。主特征与三路 DeepStack 分别对同一组成员取算术均值，其他格点剪掉。[候选、选中心与均值合并](attachments/nf4_center_selection9_local_community_v3/video_merge.py)

| 方法 | 输入和执行方式 |
|---|---|
| `A` | 一次调用，完整视频、I3 局部图和规则一起输入。视频特征全留，模型直接输出事件及对象描述。 |
| `B` | 两次调用，均不压缩。第一遍看视频和局部图，在无异常政策的条件下生成中性名册；第二遍看视频、规则和自己刚生成的名册，选出相关 ID。两次视觉编码和生成都计成本。 |
| `C50` | 一次调用，采用 C 系列的密度选点及局部均值合并，每个内部时间组输出原格点数的 50%（向上取整）。 |
| `C25` | 同一套选点、归属和均值规则，每个内部组取 25%；首尾组和局部截图仍完整保留。 |
| `C125` | 同一套规则，每个内部组取 12.5%；各组按这个名额重新选中心和分配成员。 |

**NF4 量化，中心选择与两阶段预算**

同一内部预算下，下面四种方法分别检验“该保留哪个位置”和“该输出中心原向量还是邻域均值”。

- **`S125`**：按 `C125` 的密度峰值算法选出完全相同的中心，直接取中心主特征及三路 DeepStack 原向量；其他格点全部剪掉。
- **`U125`**：首尾全留，内部组先留每隔 16 个索引的空间底线，再将剩余空间索引排序，从等分区间中点均匀取格点直至满额；仅输出原向量。
- **`M125`**：首尾及空间底线同上；内部组的余量按主特征与上一原始组同位置的余弦差从大到小选取，同分取较小索引。保留原向量。
- **`J125`**：仍按 `C125` 建候选池，把密度选点中的特征距离改为“主特征＋三路 DeepStack”分别归一化后所得四个余弦差的等权平均，并保留原空间距离项。选点后仍按主特征判定同组局部成员，四路特征各自取成员均值。

两阶段 B 的压缩用同一套 C 系列算法。每种配置的判定阶段都读取**该配置第一阶段刚生成的名册**。下表两个百分数依次是名册阶段和规则判定阶段各自的内部视频保留率。

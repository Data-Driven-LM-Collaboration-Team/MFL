# 异常—对象对应评估 V3

本口径在改进实验前冻结。它按用户的“只要知道是哪个对象”目标补充V2，不回写旧严格L3。后续版本采用相同定义，必须记录哈希；若发现定义错误，独立迁移并全部重算，不能只改不利样本。

## 通过条件

异常—对象对应成立须同时满足：实际可见的异常事件被正确理解；模型把该异常主张关联到真实主体；其描述/ID能在画面中唯一指认该主体。大类代码是否正确独立统计，不以类码代替真实事件判断。只准确描绘一个人，却把不存在的动作安在其身上，不通过。

外貌、衣着、携带物、动作、交互关系、有原生帧锚点的相对方位，均可形成身份依据。不要求bbox、九宫格、mask，不因kind/角色枚举本身不规范而直接判身份错；但被害者/旁观者被错误认作实施异常的主体是真正指代错误。无法唯一分辨的同衣多人，不由评估者补全模型未给的信息。

## 主体及完整性

逐片先由真实画面和冻结研究政策确定所有已确认事件的异常主体。包括行为实施者、驾驶者，以及自身处于异常状态的车辆/火烟/被危险抛出的物体。被害者、工具和环境不自动成为异常主体；必要关系另记。车辆在禁行区违规行驶时，驾驶者与车辆分别是可核查的真实实体，但可以通过同一条复合语言描述唯一指认二者，不强制模型拆成两个JSON对象。

- any_binding：至少一个真实异常事件的至少一个真正主体可唯一指认。只作“至少一个”覆盖，不称全片完美。
- all_binding：本片所有已确认异常事件的全部异常主体均唯一对应，且没有额外把无关者/受影响者错误绑定为异常主体。JSON角色格式错误不算身份错误；实际行为归属错算错误。
- false_binding：输出是否额外绑定到并未实施或处于该异常的对象，逐对象记录理由。至少一个正确目标和误标别人可同时存在。
- event_correct与category_correct分开保存。时间区间另记可见证据是否覆盖，不冒充时间IoU。

any/all指标须有真实视觉核查及匹配理由，不以token相似度或存在跟踪ID替代。无法核查则pending，不按成功或失败静默处理。

## 分母及证据

固定189段，167参考异常为端到端any/all主分母；输出失败保留为无可用结果，不能称预测正常。3参考正常只报告误报数，19政策不足单列，不强判。技术失败不伪造新的语义判断。可另报告有效输出条件结果，但不替代167。

原始全时段接触页和必要原分辨率帧必须实际查看；准备图片不计审核。保存全部已看文件哈希、原输出及输入哈希、对象匹配与反例。原参考仅作待核对依据，发现冲突进入争议表，保留原表并追加更正。相同Codex会话非独立盲审，human_verified=false且正式监督训练资格false。

本地评估数据不得传入新模型推理。未来候选生成只使用视频和模型自己产生的描述，不能使用此协议的参考目标、框或时间。

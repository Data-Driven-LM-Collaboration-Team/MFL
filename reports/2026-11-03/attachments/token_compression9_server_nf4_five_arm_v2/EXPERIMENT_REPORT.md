核验时间：2026-10-31T23:25:44.463024+00:00。结论：**本轮没有候选通过预注册采用/扩展护栏**。三档压缩确实减少实际视觉Token，但全部主体正确对应的片数没有净增加。B增加1片完整对应，同时出现2次严格失败并降低any/event，不能采用。

官方Qwen/Qwen3-VL-8B-Instruct revision 0c351dd01ed87e9c1b53cbc748cba10e6187ff3b，加载时NF4 double quant/BF16 compute、252语言Linear；视觉、DeepStack、embedding和lm_head保持BF16。A/C来自父v1同一批次/租约，B为同checkpoint/recipe/env的另一模型进程，B内部两阶段共享实例。社区预量化本机旧PILOT未混入本表。

原10FPS＋末帧、I3原生局部图/顺序、Prompt/政策、schema、采样/种子及8192最大输出保持版本冻结。B第一阶段中性名册不含政策，第二阶段原规则仅选择自己的ID。Cs只改视频内部Token预算，图片和文本全部保留。语义重试0，原始终态不覆盖。

## 采用决定与下一步

C50减少Token但any/event/category下降。C25在本小试主要质量项持平并减少一片错绑。C125增加一片any和event并减少一片错绑，仍没有all净增加。因此三档均未通过必须all净增加的护栏。B虽多一片all，但any/event下降、2次技术失败超过A的0，且名册增加成本，不采用。候选=null，扩展=false；不自动扩剩余数据。

下一独立机制先诊断同预算下的特征混合：固定原I3输入/Prompt/schema、首尾时间组、空间底线、选中中心及mRoPE/cache位置，仅将视频组均值改为中心原始Token，并保留同预算简单均匀选择对照。假设是特征混合可能损伤细动作/身份线索；这尚未被当前结果证明。必须独立目录、CPU合同、fresh freeze/租约/模型加载、全词logits/缓存/DeepStack/mRoPE门禁之后才产生新研究输出。服务器与本机仍按各自门禁和不重复认领推进，本机community模型不能替代官方同源模型。
